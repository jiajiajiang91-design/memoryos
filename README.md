# ◇ MemoryOS

> 把分散在多个 AI 里的上下文，变成一套持续可用的工作记忆。

[English](./README.en.md) · [下载 v0.4.0](../../releases) · [反馈问题](../../issues)

MemoryOS 是一款跨 AI 工作记忆桌面应用。它把项目目标、决定、约束、进度和方法沉淀为结构化记忆，让 ChatGPT、Claude、Gemini、Cursor、Codex 等工具在新对话里更快接上工作。

它不是聊天记录仓库，也不试图保存所有内容。MemoryOS 解决的是三个更具体的问题：**什么值得记、现在该读什么、AI 的更新能不能信。**

> **v0.4.0 · 记忆条目库版本**：记忆从整页卡片升级为带编号、类型、来源、重要度和关联关系的独立条目；支持按权重读取、会话中检索、归档与捞回，并保留旧卡片作为回退路径。

---

## 为什么做 MemoryOS

多数 AI 产品的记忆被锁在各自的工具里。换一个 AI、开一个新对话，用户就要重新解释项目背景；上下文积累得越多，又越容易出现信息过长、旧决定混入现状、AI 建议被误记成用户决定等问题。

MemoryOS 把这些问题拆成一条可控的产品链路：

| 用户问题 | MemoryOS 的处理方式 |
|---|---|
| 每次开场都要重讲背景 | 一份工作记忆供多个 AI 使用 |
| 内容太多，AI 不知道先读什么 | 在 1200 字预算内按重要度挑选开场记忆 |
| 开场没装下的旧信息找不回来 | 会话中通过 `search_memory` 按需检索 |
| 新旧决定混在一起 | 条目独立编号，被取代内容归档而非删除 |
| AI 的建议被当成用户决定 | 来源从写入时区分，所有调整提案先确认 |

## 产品闭环

### 1. 写入：把一次对话变成可复用记忆

对话结束时，AI 不再重写一整份长文档，而是提出本轮新增或需要调整的记忆条目。每条记忆保留类型和来源：用户确认、AI 建议、AI 推论或第三方资料不会混在一起。

### 2. 读取：开场推送 + 会话中按需拉取

开场时，MemoryOS 综合记忆类型、来源确定性、新鲜度、手动重要度和关联关系，在有限预算内优先选择当前最有用的内容。

如果对话中涉及开场没有带入的旧决定、历史约定或方法，连接 MCP 的 AI 可以调用 `search_memory` 主动检索。检索支持关键词、条目编号、相近说法、关联跳转和归档内容。

### 3. 治理：AI 提议，用户确认

新条目与 AI 提出的关联、合并、归档调整先进入收件箱。用户确认后才改变正式记忆；被驳回的建议进入防复提记录。过时内容可以归档，也可以随时捞回，不靠直接删除维持整洁。

## 记忆架构

### 三套库

- **项目库**：只属于当前项目的目标、决定、状态和交接
- **全局库**：跨项目生效的个人信息与协作偏好，也是「关于我」的结构化版本
- **技能库**：可以跨项目复用的方法、模板和经验

条目可以在三套库之间移动。项目记忆和技能记忆会一起参与开场选择，全局偏好则作为跨项目背景进入读取链路。

### 两种视图

- **给我看**：完整条目库，用于分组浏览、搜索、筛选、编辑、调档、归档和查看关系星图
- **给 AI 看**：实际用于开场的精简内容，实时显示字数和未入选条目数量

界面显示的重要度和 AI 的读取顺序共用同一套评分规则，避免“用户看到的”和“AI 实际读到的”不一致。

## 使用方式

### 复制粘贴：适用于任何 AI

1. 从 MemoryOS 复制开始对话指令
2. AI 读取选中的记忆并接上项目
3. 正常工作
4. 结束时让 AI 输出总结和新记忆条目，导回 MemoryOS 确认

### MCP 直连：适用于 Claude Desktop 等客户端

安装 `memoryos.mcpb` 并选择工作区后，AI 可以直接：

- 列出项目
- 读取开场记忆
- 在会话中检索历史记忆
- 把本轮总结和更新提案写入待审收件箱

网页端 AI 无法直接访问本地文件时，继续使用复制粘贴即可；两种方式进入同一套记忆系统。

## 核心能力

- 带编号、类型、来源、重要度和关系的记忆条目
- 项目库 / 全局库 / 技能库三库管理
- 给人看 / 给 AI 看双视图
- 基于类型、来源、新鲜度、手动调档和关联关系的读取排序
- 关键词、编号、筛选、相近说法与关联检索
- 可拖拽缩放的关系星图
- 归档、捞回、去重合并和取代关系
- 收件箱确认、建议驳回与防复提
- 每项目独立开启条目库读取，可随时回退到旧记忆卡片
- 完整中英双语

## 安装

### Windows 安装包

从 [Releases](../../releases) 下载 v0.4.0 的 `.exe` 或 `.msi`。

Windows 可能显示“未知发行者”（项目暂未购买代码签名证书），选择“更多信息 → 仍要运行”即可。

### 从源码运行

需要 Node.js 18+、Rust 1.70+；Windows 还需要 Visual Studio Build Tools（Desktop development with C++）。

```bash
git clone https://github.com/jiajiajiang91-design/memoryos.git
cd memoryos
npm install
npm run tauri dev
```

生产构建：

```bash
npm run tauri build
```

## 数据与隐私

MemoryOS 默认把数据保存在 `~/Documents/MemoryOS/`：

```text
MemoryOS/
├── about_me.md
├── entries/
│   ├── global.jsonl
│   └── skill.jsonl
└── projects/
    └── <项目名>/
        ├── project.json
        ├── entries.jsonl
        ├── cards.md
        ├── decisions.md
        └── sessions/
```

- 不需要账号
- 不自动读取聊天记录
- 不把记忆上传到 MemoryOS 的服务器
- 删除项目进入系统回收站，可撤销
- 条目库可以导出和导回 Markdown；复制整个工作区就是完整备份
